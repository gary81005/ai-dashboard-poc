# 標準化工具

把系統匯出的原始活頁簿（例如 CRM 的 `crm_export_20261028.xlsx`）轉成符合本專案結構規範的標準化活頁簿。有兩個入口，做的是同一件事：

- **資料集頁的「資料標準化」**：選擇原始檔後在瀏覽器轉換，顯示各表列數與資料品質檢核的問題，再選擇「下載標準化檔」或「匯入為資料集」。
- **`npm run standardize`**：在本機轉換，適合批次處理或檢查產出檔。

```bash
nvm use   # 需要 Node 24 以上（直接執行 TypeScript）
npm run standardize -- docs/poc/crm_export_20261028.xlsx docs/poc/CRM_標準化資料庫_20261028.xlsx
```

- 依工作表名稱自動辨識來源；也可以加 `--spec=crm` 指定。缺少必要的工作表或欄位時，會列出缺了哪些。
- 沒給輸出檔時，寫在原始檔旁邊，檔名加上「\_標準化」。
- 原始檔和產出檔通常是真實資料，請放在 `docs/poc/`（已被 `.gitignore` 排除），不要 commit。

程式的位置：

| 檔案                                            | 內容                                          |
| ----------------------------------------------- | --------------------------------------------- |
| `src/utils/standardize/`                        | 通用引擎（純邏輯）：型別、值處理、公式、流程  |
| `src/utils/standardize/specs/`                  | 各來源的設定；`index.ts` 是清單與辨識規則     |
| `src/services/standardizeWorkbook.ts`           | 讀取原始檔 → 轉換 → 寫出 xlsx，網頁與指令共用 |
| `src/components/datasets/StandardizeButton.tsx` | 資料集頁的按鈕與對話框                        |
| `scripts/standardize/cli.ts`                    | `npm run standardize` 的進入點                |

## 兩條原則

1. **原始值不刪不改**：只做型別正規化和新增衍生欄位。
2. **資料品質問題不修補**：只標記旗標，列入「資料品質檢核」，交給業務單位判斷。

## 通用流程

引擎在 `src/utils/standardize/`，是純邏輯、和資料來源無關；每種來源寫一份設定檔，描述要產生哪些資料表、每個欄位從哪裡來。

| 步驟            | 做什麼                                                                                 | 設定檔怎麼寫                                                           |
| --------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1. 欄位整理     | 選欄、更名、拿掉冗餘欄位（改用維度表 join）                                            | `rowTable` 的 `columns` 只列要的欄位，取值時讀原始欄名                 |
| 2. 清理與型別   | 缺值（空白、「-」）寫成「未提供」；不換行空白換成一般空白；文字轉日期、數字、百分比    | `text`、`keep`、`toDate`、`toNumber`、`toRatio`                        |
| 3. 衍生欄位     | 日期展開成年、月、年月、季；0/1 旗標；拆解組合字串；抽前綴；查另一張表的鍵是否存在     | `datePart`、`flag`、`splitFirst`、`bracketPrefix`、`ctx.valuesOf`      |
| 4. 萃取維度表   | 從多個欄位收集不重複的鍵（排除缺值、排序），屬性從出現過的原始列推導                   | `rows: distinctKeys([...])`，屬性用 `KeyEntry.hits`、`mostCommon`      |
| 5. 主檔加旗標   | 逐列（屬性是否完整）或跨列（名稱是否重複）的檢查                                       | `rows: sheetRows('客戶')`，跨列用 `ctx.countOf`                        |
| 6. 日曆         | 日期欄位涵蓋的每一年各 12 個月                                                         | `rows: calendarMonths([...])`                                          |
| 7. 彙總表       | 列是各事實表「期間 × 鍵」的聯集；指標寫成 COUNTIFS／SUMIFS 公式，比率寫成 IF(分母=0,…) | `aggregateTable`，公式用 `formula.ts` 的 `countIfs`、`sumIfs`、`ratio` |
| 8. 資料品質檢核 | 每條規則是「符合條件的筆數 ÷ 母數」，寫成公式                                          | `checks`                                                               |
| 9. 中繼資料     | 使用說明、欄位定義（依每個欄位的代碼、型別、單位、資料來源自動產生）                   | `readme`；欄位定義不用寫                                               |

輸出時每張表都是 Excel 表格物件（`tbl_fact_`、`tbl_agg_`、`tbl_dim_` 前綴代表種類），標題列凍結，依型別套數字格式。字色沿用 CRM 標準化檔的規則：資料值藍字、同表公式黑字、跨工作表連結綠字。公式的計算結果會一併寫進檔案，不用開 Excel 重算就看得到數字。

## 新增一種來源

1. 在 `src/utils/standardize/specs/` 新增一個檔案，匯出 `spec: StandardizeSpec`（可以照 `crm.ts` 改），並在同一資料夾的 `index.ts` 加上一筆：顯示名稱，以及辨識用的必要工作表與欄位。
2. `tables` 依輸出順序排列：彙總表只能引用排在它前面的資料表。使用說明、資料品質檢核、欄位定義固定排在最前面，不用列。
3. 每個欄位寫中文欄名、代碼、型別、資料來源、欄寬和取值函式；單位或說明（`unit`）會顯示在欄位定義。
4. 在 `tests/` 用**模擬資料**寫測試（參考 `tests/standardize.test.ts`），不要放真實資料。
5. 有一份已經做好的標準化檔可以對照時，用它逐格比對產出檔，確認規則沒有寫錯。

## 已知的坑

- **讀大檔要用 ExcelJS 的完整讀取器**。串流讀取器（`WorkbookReader`）切塊時會把多位元組的中文字切斷，讀出「��」亂碼。
- **`worksheet.columnCount` 每次存取都會掃過整張表**，不能放在迴圈條件裡，否則幾萬列的檔案會慢到幾十分鐘。
- **小數加總取 15 位有效數字**（和 Excel 一致），否則會出現 21158999.529999997 這種浮點誤差。
