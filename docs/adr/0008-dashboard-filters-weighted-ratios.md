# 0008. 儀表板篩選、加權比率與報表型樣式（設定格式 v2）

- 狀態：已採納（補充 [0004](0004-field-roles-and-aggregation.md)、[0005](0005-dashboard-config-schema-v1.md)）
- 日期：2026-10-13

## 背景

我們拿一份實際在用的業務看板（崗位人員業績看板，單一 HTML，資料由 Python 前處理成 JSON 內嵌）來比對，看這套系統能不能做出同樣的內容。差距主要在五個地方：

1. **沒有整個儀表板共用的篩選。** 看板的核心操作是「選區域、選人員」，所有區塊一起跟著變；0004 只有 widget 層級的篩選。
2. **比率算不對。** 看板上的重點數字幾乎都是比率（業績達成率、YTD 達成率、台數達成率、商機健康度、拜訪覆蓋率），分組後必須是「分子加總 ÷ 分母加總」。0004 只做到非加權平均加上 ⚠ 提示。
3. **沒有警示色。** 達成率依 80% / 100% 分紅、黃、綠，未達標的列標紅。
4. **不能依數值排序。** 人員達成率排名需要由高到低。
5. **沒有說明文字。** 每個區塊都有計算口徑的說明，頁尾有指標定義。

另外，業務規則（H/M/L 分級、產品別名、飛秒與傳統的分類、1–6 月實際結案加 7–12 月自報預估）不放進這套系統，由資料前處理算成欄位，再輸出成符合結構規範的活頁簿。

## 決策

### 1. 儀表板篩選

- `Dashboard.filters?: DashboardFilter[]`，`DashboardFilter = { field: FieldRef }`。**只記錄用哪些欄位篩選，不記錄選了哪些值。**
- 選取的值只在當次瀏覽有效，存在 `uiStore.filterValues`（記著所屬的儀表板 id），換頁就清空。選值不會讓儀表板變成「未儲存」。
- 套用方式：每個 widget 查詢時，篩選條件是自己的 `filters` 加上儀表板篩選中**這張資料表找得到的欄位**（依 [0003](0003-field-identity-and-rebinding.md) 先比標頭、再比代碼）。找不到的略過，卡片上會註明「未套用儀表板篩選」。兩者之間是 AND。
- 下拉選單的選項是所有看得到的資料表裡該欄位出現過的值，並先套用其他已選的儀表板篩選。所以選了區域之後，人員清單只剩該區域的人。
- 編輯模式下把維度欄位拖到格線上方的篩選列，就能新增一個篩選。拖放不限資料表，因為篩選列不屬於任何 widget。

### 2. 加權比率（實作 0004 的「下一階段」）

- `Field.ratioOf?: { numerator: string; denominator: string }`，指向同一張資料表的兩個欄位標頭。
- **自動判斷**：解析時保留公式文字。一欄裡的每個公式都是同一組 `分子/分母`，或 `IF(分母=0, 0 或 "", 分子/分母)`，而且都指向同一列的儲存格時，就記下分子分母，並把這欄標成比率。跨工作表、`SUM`、差額之類的公式一律不處理。
- **手動指定**：資料集頁的欄位清單可以替比率欄位指定分子分母，記錄方式和角色覆寫相同（`userOverride` 加上 `'ratioOf'`），切換資料來源時會沿用。
- **彙總**：有 `ratioOf` 時，`sum` 與 `avg` 都改算加權比率；`min`、`max` 仍取每一列自己的比率，`count` 不變。加權比率**只計入分子、分母都是數字的列**，例如拜訪目標只有 1–7 月時，8 月以後的實際拜訪數不會算進分子。分母加總為 0 時是空值。加權比率不顯示 ⚠，槽位上的彙總方式顯示成「加權比率」。
- 解析時順便修正一個既有問題：ExcelJS 的 `cell.value` 會把結果是 0 的公式當成沒有結果，所以改讀 `cell.result`。在這之前，算出 0% 的比率會變成空白。

### 3. 門檻上色

- `Thresholds = { warning, success }`：值小於 `warning` 是紅，介於兩者之間是黃，大於等於 `success` 是綠。比率也以小數儲存（80% 存成 0.8），編輯器依欄位格式用百分比輸入。
- 套用在 `bar`（長條依數值變色，用 MUI X 的 piecewise `colorMap`）、`kpi`（數字變色並加上狀態標籤），以及 `table`（只套用在比率欄位；`highlightRows` 會把有欄位落在紅色區間的整列標色）。
- 顏色一律用 theme 的 `error`、`warning`、`success`。

### 4. 排序、前 N 名、合計

- `bar.options.sort` / `limit`：依第一個量值排序分類，再只留前 N 個。有分組時，排序值是把整個分類的資料列重新彙總，而不是把各組的值相加：比率欄位相加沒有意義（80% + 120% 不是 200%），重新彙總才會得到正確的加權比率。橫式長條加上由大到小排序，就是排名圖。
- `table.options.sort`：預設依第一個數值欄排序，使用者仍可以點欄位標頭改變排序。
- `table.options.totals`：在表格底部顯示合計，每一欄用同一套彙總規則對篩選後的全部資料列計算，比率欄位是加權比率；沒有分子分母的比率欄位和維度欄位不合計。

### 5. 說明文字

- `WidgetBase.description?`：顯示在標題下方，用來寫計算口徑。
- 新增 `text` 類型（`TextWidget`）：`content` 是純文字並保留換行，不綁資料表，沒有槽位。用於區塊說明和指標定義。不引入 Markdown 套件。

### 格式版本

`SCHEMA_VERSION` 由 1 升到 2。以上全部都是**新增的選填欄位**，v1 的記錄本身就是合法的 v2，`migrateRecord` 不需要轉換。v1 的程式讀到 v2 的記錄時會依規則拒絕（「格式比目前程式還新」）。

## 影響

- 舊資料集沒有 `ratioOf`，因為當初解析時沒有保留公式。要重新上傳活頁簿，或手動指定分子分母，才會改成加權。範例活頁簿重新上傳後，`營業利益率` 和 `平均客單價` 都會自動變成加權。
- 加權比率依賴分子、分母欄位留在同一張表。前處理產出活頁簿時，比率欄位要寫成同列公式，不要寫成數值。
- 一張表格只有一組門檻。比率欄位的尺度不同時（例如達成率 0.8 / 1 和健康度 3 / 5），要拆成兩個 widget。
- 儀表板篩選以標頭比對，所以每張資料表的同一個維度要用同一個標頭，例如每張表都用 `區域`、`人員`。這也成了前處理產出活頁簿的規範之一。
- 選的值不會保存，重新整理或離開儀表板就要重選。

## 考慮過的其他方案

- **篩選值跟著儀表板儲存**：使用者決定只在當次瀏覽有效，避免「上次選的人」變成別人打開時的預設畫面。
- **通用公式編輯器（計算欄位）**：彈性最大，但要設計運算式語法和錯誤處理。比率已經能從 Excel 公式取得，其餘的計算交給資料前處理。
- **新增 `weighted` 彙總方式**：要改 `Agg` 的意義，而且使用者要自己記得改選；直接讓有分子分母的欄位在 `sum`/`avg` 時加權，使用者不用多做任何事。
- **跨 widget 的點擊聯動、展開明細、月份頁籤、H/M/L 看板**：屬於特定報表的流程，放進通用的拖拉模型會讓槽位設計複雜很多。改用儀表板篩選、widget 篩選和以「分級」分組的表格代替。
