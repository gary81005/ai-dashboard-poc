# 0011. 值標籤：原始值換成好讀的文字（設定格式 v3）

- 狀態：已採納（補充 [0004](0004-field-roles-and-aggregation.md)、[0005](0005-dashboard-config-schema-v1.md)、[0008](0008-dashboard-filters-weighted-ratios.md)）
- 日期：2026-10-29

## 背景

活頁簿裡常有用代碼表示的欄位：

- 0/1 旗標：`是否回診`、`是否合格打者`
- 文字代碼：性別 `M` / `F`、等級 `A` / `B` / `C`

圖表、篩選和表格直接顯示這些代碼，看的人要自己對照。Excel 的 TRUE / FALSE 更糟：被當成文字，畫面上顯示的是英文的 `true` / `false`，也沒辦法當量值計算。

另一方面，0/1 欄位當量值時很有用：加總是「是」的筆數，平均是「是」的比例。所以不能只在 Excel 裡把它改成文字「是 / 否」，那樣就失去了計算能力。

## 決策

### 1. 只改顯示、不改資料

- `Field.valueLabels?: Record<string, string>`：原始值 → 顯示文字。key 是 `categoryKey` 轉成的字串，例如 `{ "1": "是", "0": "否" }`。
- 分組、排序、篩選一律用原始值。只有輸出到畫面的那一步才換成標籤：分類軸、圖例與系列名稱、圓餅、散佈圖的點、KPI 趨勢、資料表格的格子、篩選選項與摘要、編輯模式的欄位提示卡。
- 所以改標籤文字或停用標籤，已設好的篩選都不會失效。排序也照原始值，例如 0、1 是「否、是」，月份代碼 1～12 維持原本的順序。
- 沒有對照的值照常顯示原始值，空白仍是「（空白）」。
- 兩個值被設成同一個標籤時，在後面補上原始值區分，例如「其他（3）」。座標軸會把同名的刻度合併成一格，不區分的話資料會錯位。

### 2. 兩層開關，隨時切回原始值

- **欄位層級**：`Field.showValueLabels?: boolean`。設成 false 時保留對照但不套用，所有儀表板一起改回原始值。在資料集頁的「值標籤」對話框切換。
- **元件層級**：`Widget.rawValues?: boolean`。這個元件不套用任何欄位的標籤。元件設定的樣式區只在用到有標籤的欄位時，才出現「顯示原始值」開關。
  - 實作上由 `withRawValues` 把整張表的標籤停用後再查詢，查詢與格式化的程式不必知道有這個開關。
  - `rawValues` 放在 `WidgetBase` 而不是各類型的 `options`，因為所有類型都適用；切換圖表類型時保留。

### 3. 量值：只有 0/1 欄位套用

0/1 欄位以 1 的標籤作為計數對象：

| 彙總        | 完整（tooltip、表格、KPI 小字） | 精簡（座標軸、KPI 大字） |
| ----------- | ------------------------------- | ------------------------ |
| 平均        | 是 35.0%                        | 35.0%                    |
| 加總        | 是 120 筆                       | 120                      |
| 最小 / 最大 | 是 / 否                         | 是 / 否                  |
| 計數        | 30（照一般規則）                | 30                       |

- 判斷條件（`isBinaryLabeled`）：數值欄位，對照只有 `0`、`1` 兩個 key，而且至少有 `1`。
- 非二元的對照（`M → 男`、`1 → 甲`、`2 → 乙`）拿來當量值時，加總或平均沒有意義，維持顯示數字。
- 套用標籤的 0/1 欄位不顯示單位，因為文字已經寫了「筆」。

### 4. 上傳時自動套用

- Excel 的 TRUE / FALSE 在解析時轉成 1 / 0，資料型別是整數。這樣兩種寫法走同一套規則，量值也能算比例。
- 整數欄位的值只有 0 和 1，而且**兩種值都出現**，就自動加上 `1 → 是`、`0 → 否`。
  - 只出現一種值的欄位通常不是旗標，例如全是 1 的「件數」，不套用。
  - 例外：原本是 TRUE / FALSE 的欄位一定是二元，只出現一種也套用。
- 欄位定義的單位寫成 `1=是`、`1=有,0=無`、`1='合格'` 這類格式時，用單位裡的文字；只寫了 1 的標籤時，0 用反義詞（是 / 否、有 / 無、已 / 未），沒有反義詞就加「非」。
- 角色不變，維持原本推斷的結果（0/1 欄位通常是量值）。標頭是「是否 / 有無」的欄位，欄位健檢照舊會建議改成維度（[0010](0010-chart-recommendation-rules.md)）。
- 資料集頁的欄位健檢列出「已自動套用值標籤」的欄位。可以逐一「改回原始值」，或按「知道了」全部保留；做過任何一個動作，或在對話框修改過，就記成 `userOverride: 'valueLabels'`，之後不再列出。

### 5. 編輯介面

- 資料集頁每個欄位有一個「值標籤」按鈕，顯示目前的對照，或「已停用」、「設定」。
- 對話框列出欄位實際出現的值，以及對照裡有、但資料裡已經沒有的值，各自輸入標籤；另有「顯示值標籤」開關和「全部清除」。
- 不同值超過 50 種（`MAX_LABELED_VALUES`）的欄位不提供設定。代碼型欄位通常只有十幾種值；上百種的大多是門市名稱這類，本身就看得懂。

### 6. 沿用與匯出

- 值標籤存在資料集上，和角色覆寫一樣。切換資料來源時，`carryOverrides` 沿用使用者修改、停用或清除過的對照。
- 匯出的 JSON 不帶值標籤，因為匯出檔只有儀表板設定和欄位簽章（[0005](0005-dashboard-config-schema-v1.md)）。元件的 `rawValues` 是儀表板設定，會跟著匯出。

### 格式版本

`SCHEMA_VERSION` 由 2 升到 3。`Field.valueLabels`、`Field.showValueLabels`、`Widget.rawValues` 都是**新增的選填欄位**，v2 的記錄本身就是合法的 v3，`migrateRecord` 不需要轉換。

## 影響

- 舊資料集不會補上自動偵測的值標籤，因為偵測只在解析時進行。需要的話在資料集頁手動設定，或重新上傳活頁簿。
- 舊資料集裡的 TRUE / FALSE 欄位仍是文字 `true` / `false`；重新上傳才會轉成 1 / 0。
- 值只有 0 / 1 的一般整數欄位也會被自動套用，例如某個「退貨數」剛好只有 0 和 1。這種情況在欄位健檢按「改回原始值」即可。
- 篩選選項的文字來自第一張有這個欄位、而且有設對照的資料表。儀表板篩選跨多張表時，同一個欄位在不同表要用同一組對照，否則會以第一張表為準。

## 考慮過的其他方案

- **直接改寫資料**（把 1 存成「是」）：最簡單，但失去「是」的筆數與比例，而且關掉標籤就回不去。
- **只做 0/1**：代碼型欄位（性別、等級、狀態碼）同樣需要，介面幾乎一樣，所以做成通用的。
- **自動偵測只出現在欄位健檢、由使用者按「套用」**：使用者要求自動偵測，直接套用並提供兩層開關切回原始值，比多一個步驟更省事。
- **自動偵測時一併改成維度**：會看不到「是 35%」。需要分組時再手動改角色即可。
- **依標籤文字排序**：標籤可能被修改，排序會跟著跳動；照原始值排序最穩定。
- **每個槽位各自切換原始值**：一張圖通常只有一兩個欄位有標籤，逐欄切換的介面繁瑣，用處不大。
