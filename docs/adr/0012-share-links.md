# 0012. 分享連結：不用登入、只給算好的結果

- 狀態：已採納（修改 [0007](0007-supabase-storage.md) 的「只能存取自己的資料」），已實作
- 日期：2026-10-30

## 背景

儀表板只有擁有者自己看得到（[0007](0007-supabase-storage.md)）：三張表的 RLS 都是 `user_id = auth.uid()`，`anon` 什麼都不能存取。想給主管或同事看，只能匯出 JSON 請對方匯入，對方還得有同一份活頁簿。

難處在於圖表是在瀏覽器裡算的（`utils/query.ts`）：開啟儀表板時，會把整張資料表的原始資料列下載下來再彙總。如果分享時沿用這個流程，拿到連結的人打開開發者工具，就能看到每一列，例如客戶名稱、業務姓名，不只是圖上的數字。上傳的活頁簿常常是真實資料，這不能接受。

## 決策

### 1. 誰能看、看到什麼

- **拿到連結的任何人都能打開，不用登入。** Supabase 的註冊是開放的，要求登入也擋不了什麼，只會讓看的人多一道手續。
- **看的人只拿到算好的圖表結果（分享結果），不會拿到原始資料列，也拿不到資料集的欄位清單。**
- **只能看。** 可以滑鼠移上去看數值、資料表格排序和捲動、窄螢幕自動重排（[0009](0009-responsive-layout.md)），這些都只用已經算好的結果。不能匯出、不能改篩選，也沒有編輯模式。
- 頁面只顯示儀表板名稱、說明、元件，以及「最後更新於」（分享結果的寫入時間），**不顯示擁有者的 email**：連結可能被轉傳，email 是個人資料。
- 分享頁加上 `<meta name="robots" content="noindex">`，連結被貼到公開網頁時，搜尋引擎不會收錄。

### 2. 分享結果怎麼產生

- 每個圖表元件現在都是「查詢一次 → 畫圖」。查詢那一步抽成純函式 `computeWidget(widget, ctx)`，回傳可以存成 JSON 的結果；元件改成拿結果畫圖。擁有者的畫面和分享頁共用同一套畫圖元件。
- **擁有者每次按「儲存」時，瀏覽器順便重算分享結果。** 編輯時原始資料已經載入，重算只是多跑一次查詢。看的人看到的永遠是「最後一次儲存」的版本，和「按儲存才寫入」的規則一致（[0007](0007-supabase-storage.md)）。
- **儲存儀表板和更新分享結果在同一個 transaction 裡**（RPC `save_dashboard`）：要嘛都成功、要嘛都失敗。失敗時維持「未儲存」，再按一次就重試，和現在的行為一樣。沒有分享連結的儀表板只寫入設定。
- **儀表板篩選一律算「全部」。** 篩選選的值只存在 `uiStore`，不會存檔；如果用按儲存當下的選擇，分享出去的可能只剩某一區，看的人會誤會。元件篩選存在設定裡，照設定套用。
- 值標籤（[0011](0011-value-labels.md)）和 `Widget.rawValues` 照擁有者畫面上的樣子套用；文字元件的內容照原樣分享。
- 欄位遺失的元件，結果就是那則錯誤訊息，和擁有者畫面上一樣。

### 3. 會露出逐筆資料的元件

「只給算好的結果」擋不住結果本身就是逐筆資料的元件：

- 沒有彙總的資料表格（明細表）
- 散佈圖的點，例如每位客戶一個點
- X 軸是代號／名稱的長條圖與排行

這些元件**照畫面上的內容分享**。擁有者放上儀表板的，就是他願意給人看的內容；但分享對話框會列出這些元件，讓擁有者知道哪些元件會露出逐筆資料，再決定要不要分享。系統不會自動把它們藏起來。

### 4. 連結的管理

- **一個儀表板最多一條連結。** 可以建立、複製、撤銷。撤銷就是刪除這條連結和它的分享結果，資料庫裡不留已撤銷的分享結果；之後可以重新建立，網址會換成新的。
- **到期日**：建立時選 7／30／90 天或永不過期，預設 30 天。之後可以延長或縮短，網址不變。
- **失效的情況**：撤銷、過期、刪除儀表板、刪除儀表板目前用到的資料集。刪除資料集通常就是不想讓這份資料再出現，所以分享結果也不再提供。
- 看的人遇到失效的連結，一律顯示「這個連結已失效，請向分享的人索取新連結」，不說明原因，避免讓拿到連結的人推測擁有者做了什麼。擁有者在分享對話框看得到詳細狀態。
- 入口是儀表板頁的「分享」按鈕。儀表板清單的卡片上，有分享中的連結就顯示「分享中」，讓擁有者記得哪些儀表板正對外公開。
- 建立連結時有未儲存的變更：分享的是上次儲存的版本（`appStore.draftBase`），對話框會提醒。

### 5. 資料庫

新增一張表，現有三張表的 RLS 都不變，`anon` 照樣讀不到它們。

| 表                 | 一筆是       | 主要欄位                                                                                |
| ------------------ | ------------ | --------------------------------------------------------------------------------------- |
| `dashboard_shares` | 一條分享連結 | `token uuid`、`dashboard_id`、`snapshot jsonb`（分享結果）、`snapshot_at`、`expires_at` |

- 主鍵是 `(user_id, dashboard_id)`，所以一個儀表板最多一條連結。外鍵 `(user_id, dashboard_id) → dashboards` 加上 `on delete cascade`，刪除儀表板時連結跟著刪除。
- `token` 用 `gen_random_uuid()` 產生（122 位元的隨機數），猜不到；有唯一索引。前端沒有 `token` 欄的寫入權限，一律由資料庫產生。
- `snapshot_at` 是分享結果的寫入時間，分享頁顯示成「最後更新於」；只改到期日時不變。`expires_at` 是 null 代表永不過期。
- RLS 只開放給擁有者。
- **看的人不直接讀任何表**，只能呼叫 `get_shared_dashboard(token)`，這是開放給 `anon` 的 `security definer` 函式，`search_path` 設成空字串。它先檢查連結存在（撤銷過就不存在了）、沒過期，儀表板目前的 `datasetId` 指向的資料集仍存在且是 `ready`，才回傳 `{ snapshot, snapshotAt }`；否則回傳 null，前端顯示失效訊息。
- **儲存改用 `save_dashboard(...)`**：用 `security invoker` 執行，RLS 照常生效。在同一個 transaction 裡更新 `dashboards`，以及這個儀表板的分享結果（有連結時）。

### 6. 分享結果的格式

- 只放畫面上會顯示的東西：版面（`layout`）、每個元件的類型、標題、說明、樣式選項、文字內容、元件篩選的摘要文字，以及 `computeWidget` 的結果。
- 結果裡帶著用到的欄位的標頭、資料型別、單位與值標籤，格式化數字時需要；這些本來就顯示在圖上。不放原始資料列和資料集的欄位清單。
- 帶自己的版號 `SNAPSHOT_VERSION`，和儀表板設定的 `SCHEMA_VERSION` 分開。分享結果每次儲存都會重算，所以不寫轉換步驟；分享頁讀到不認得的版號時，顯示「這個分享連結需要更新，請分享的人開啟儀表板並儲存一次」。
- 儀表板設定的格式不變，不用提高 `SCHEMA_VERSION`（[0005](0005-dashboard-config-schema-v1.md)）。

### 7. 前端

- **網址是 `?share=<token>`。** 專案沒有 router；啟動時讀到這個參數，就不檢查登入，直接顯示分享頁。用 query string 也不用改 Vercel 的路由設定。
- 擁有者自己打開分享連結，看到的也是分享頁，和別人看到的一樣。
- 存取資料庫一樣經過 `services/`（新增 `services/shareService.ts`），UI 不直接 import Supabase client。
- 登入後載入儀表板清單時，一併載入自己的分享連結，供「分享中」標籤和儲存流程判斷要不要重算分享結果。

### 實作順序

1. 把查詢抽成 `computeWidget`。這步只是重構，畫面不變。
2. migration：`dashboard_shares`、`get_shared_dashboard`、`save_dashboard`，接著 `db:push`、`db:types`。
3. 儲存流程改成同時更新分享結果。
4. 分享頁與 `?share=` 的判斷。
5. 分享對話框與清單上的「分享中」標籤。

## 影響

- 不用登入就能看儀表板，但看不到原始資料列；「只能存取自己的資料」改成「原始資料只有擁有者讀得到，分享結果拿到連結的人都讀得到」。
- 分享的內容只在擁有者按「儲存」時更新。擁有者只開啟、沒儲存，分享頁不會變。
- 有分享連結的儀表板，每次儲存多寫一份分享結果；明細表格很長時，分享結果也會跟著變大。
- 看的人不能篩選。想給不同對象看不同區域，目前只能另外做一份儀表板，用元件篩選固定範圍。
- `computeWidget` 是純函式，可以用 Vitest 測試（測試範圍見 [0010](0010-chart-recommendation-rules.md) §8）。原本只能在畫面上確認的查詢結果，現在有機會補測試。

## 考慮過的其他方案

- **看的人也下載原始資料列，在瀏覽器裡算**：改動最小，篩選也能用，但開發者工具裡看得到每一列原始資料。
- **只開放儀表板用到的資料表**：比整個資料集少，但露出的仍是原始資料列，問題沒有解決。
- **把彙總搬到資料庫端，看的人開啟時即時算**：結果永遠最新、篩選也能用，但等於重寫整個查詢引擎，和 0007「彙總在前端進行」的決定衝突。
- **分享時拍一次快照，之後不再更新**：擁有者改了儀表板還要重新分享，容易忘記。
- **先存儀表板、再另外更新分享結果**：分享結果更新失敗時，儀表板已經存好、畫面也不再是「未儲存」，沒有自然的重試方式，會出現儀表板是新版、分享出去的卻是舊版。
- **要求看的人登入，或限定 email**：註冊是開放的，要求登入擋不了什麼；限定 email 要另外做名單與寄信流程，目前用不到。
- **一個儀表板多條連結（各自命名、各自到期）**：給不同對象分開撤銷比較方便，但介面和資料表都變複雜。之後需要時，把主鍵改成 `token` 就能擴充。
- **用擁有者按儲存當下的儀表板篩選**：篩選值沒有存檔，分享出去的範圍會取決於擁有者當時剛好選了什麼。
