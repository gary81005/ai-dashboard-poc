# 0003. 欄位識別與換檔時的重新對應

- 狀態：已採納
- 日期：2026-10-05

## 背景

最自然的使用情境是：每個月上傳新的報表，沿用同一套儀表板。所以設定 JSON 裡「某張圖用了哪個欄位」的記錄方式，必須在換檔之後還對得上。

有三種可以用來識別欄位的資訊，各有缺點：

- **中文標頭**：每個檔案一定有，但標頭改名就對不上。
- **欄位代碼**（`欄位定義` 裡的英文代碼）：最穩定，但 `欄位定義` 這張表可有可無，沒有它就沒有代碼。
- **欄位位置**（例如 G 欄）：插入一欄之後就全部錯位。

## 決策

1. **資料表**用 `tbl_` 表格物件名稱識別，存在 `table.key`。活頁簿沒有表格物件時，改用工作表名稱。另外一律記下 `sheetName`，作為顯示和比對的備援。
2. **欄位**一律記成欄位參照 `FieldRef = { header: string; code?: string }`。中文標頭是主鍵，有欄位代碼時一併記下。**不記欄位位置。**
3. **資料集庫**：每次上傳的活頁簿都存成一個資料集，可以命名、刪除。每個儀表板指向**一個**資料集（`datasetId`）；同一個儀表板裡的 widget 不能來自不同資料集。
4. **切換資料來源（rebind）時的對應規則**，對每個 widget 依序比對：
   1. 資料表：先比 `table.key`，找不到再比 `sheetName`。
   2. 欄位：先比 `header`（完全相同）；對不上時，如果雙方都有 `code`，再比 `code`。用 `code` 對上時，把參照裡的 `header` 更新成新的標頭。
   3. 兩者都對不上的欄位參照，列入該 widget 的「欄位遺失」。widget 上顯示標示，讓使用者重新指定欄位，其他 widget 照常顯示。
5. **使用者覆寫跟著資料集走**（角色、比率標記，見 [0004](0004-field-roles-and-aggregation.md)）。切換資料來源時，把舊資料集上的覆寫依欄位參照，複製到新資料集裡「還沒被覆寫」的對應欄位。
6. **刪除資料集**時，如果還有儀表板指向它，要先警告使用者。確定刪除後，這些儀表板的所有 widget 都會顯示「資料集遺失」，直到使用者切換資料來源為止。

## 影響

- 標頭改名，而且活頁簿沒有 `欄位定義` 的話，欄位就對不上，只能讓使用者手動重新指定。這是可以接受的退化方式：欄位遺失有明確標示，不會靜默地畫出錯的資料。
- 因為只認標頭和代碼，欄位的順序可以任意調整，也可以插入新欄位，都不影響既有的儀表板。

## 考慮過的其他方案

- **只用欄位代碼**：沒有 `欄位定義` 的活頁簿就完全無法使用。
- **用欄位位置**：插入一欄就全部錯位，而且錯位時不會報錯，會靜默地畫出錯誤的圖。
- **一個 widget 可以各自選資料集**：欄位對應和 JSON 格式都會複雜很多，POC 不需要。
