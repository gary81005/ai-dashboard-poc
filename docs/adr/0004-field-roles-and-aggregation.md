# 0004. 欄位角色與彙總規則

- 狀態：已採納
- 日期：2026-10-05

## 背景

使用者把 `區域` 拖到 X 軸、`營業額` 拖到 Y 軸時，北區 4 家店 × 12 個月共 48 列，必須合併成一個數字。所以系統必須知道兩件事：哪些欄位是分類（維度）、哪些是數值（量值）；數值要怎麼合併（彙總）。

**`欄位定義` 的資料型別不足以判斷這兩件事。** 從範例檔可以看到：

- `年`、`月`、`最佳月份`、`營業額排名` 的型別是「整數」，但實際上應該當分類用，不能加總。
- `平均客單價`、`日均來客數` 的型別是「數值」，單位分別是 NT$ 和人次/日，和 `營業額` 看起來沒有差別。但它們是**比率**：加總沒有意義，直接平均也會讓小店和大店的權重一樣。
- 只有「百分比」型別（營業利益率、份數佔比、營業額月增率）能直接判斷出是比率。

## 決策

### 角色判斷：先自動判斷，使用者可以覆寫

依下列規則判斷，第一條符合的就採用：

1. 型別是 `text` 或 `date` → **維度**。
2. 欄位的值全部符合 `^\d{4}-\d{2}$`（年月） → **維度**。
3. 標頭**完全等於** `年` 或 `月`，或者**以** `月份`、`排名`、`代號`、`編號` **結尾** → **維度**。
4. 其他數值型別 → **量值**。

> ⚠️ 規則 3 要用「完全相同」和「結尾比對」，**不能用「包含」**。否則 `年營業額`、`月租金`、`年來客數` 這類量值也會被誤判成維度。

使用者可以在欄位清單上手動切換角色。切換結果記在該資料集的欄位上（`role` + `userOverride`），切換資料來源時沿用（見 [0003](0003-field-identity-and-rebinding.md)）。

### 比率判斷

- 自動判斷：型別是 `percent`（來自 `欄位定義` 的「百分比」），或者 Excel 數字格式含有 `%` → `ratio: true`。
- 手動標記：使用者可以在欄位清單上把欄位標成「比率（不可加總）」，例如 `平均客單價`、`日均來客數`。記錄方式和角色覆寫相同。

### 彙總

- 每個放進數值槽位的欄位，由使用者選擇彙總方式：`sum` / `avg` / `count` / `min` / `max`。
- 預設值：
  - 一般量值 → `sum`
  - 比率欄位 → `avg`，並在 widget 上顯示「⚠ 非加權平均」提示
  - 把維度放進數值槽位（例如 KPI 卡的 `value`） → `count`
- 散佈圖的 `detail` 槽位、KPI 卡的 `trend` 槽位，也都依上面的規則彙總。

### 其他預設

- **篩選**只做 widget 層級（`filters[]`）。v1 至少支援維度欄位的 `in`（值在清單中）。
- **排序**：被判斷成時間的維度（規則 2 或日期型別）照時間先後排列；其他維度照資料出現的順序。
- **數字顯示**：優先使用 Excel 儲存格的數字格式（`numFmt`），沒有的話參考 `欄位定義` 的單位。比率欄位顯示成百分比。

## 影響

- 比率欄位在分組彙總後是**非加權平均，數字是錯的**，只能靠 ⚠ 提示讓使用者知道。想看精確的比率，可以直接用 `門市年度彙總`、`月度彙總` 這類已經在 Excel 裡算好的彙總表，因為它們每組只有一列，不需要再彙總。
- 自動判斷一定會有例外，所以「使用者可以覆寫」是必要功能，不能省略。

## 下一階段：加權比率

ExcelJS 讀得到公式本身（見 [0002](0002-excel-parsing-exceljs.md)），例如 `營業利益率 = IF(G2=0,0,N2/G2)`，也就是 `營業利益 / 營業額`。所以可以從公式推出分子和分母，分組時改用「分子加總 ÷ 分母加總」，算出正確的加權比率。v1 不做這個功能，但解析時要保留公式文字，日後才能接上。
